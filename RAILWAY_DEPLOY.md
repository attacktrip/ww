# Развёртывание на Railway — пошаговый гайд

В этом руководстве описано, как выложить проект (сайт + Telegram-бот) на [Railway](https://railway.app).

---

## Что нужно заранее

1. **Аккаунт на Railway**  
   Зарегистрируйтесь на [railway.app](https://railway.app) (можно через GitHub).

2. **Репозиторий на GitHub**  
   Проект должен быть в Git-репозитории и запушен на GitHub.

3. **Токен бота**  
   Получите токен у [@BotFather](https://t.me/BotFather) в Telegram.

4. **Chat ID админа**  
   Узнать свой ID можно, например, у [@userinfobot](https://t.me/userinfobot) в Telegram.

---

## ⚠ Важно: если Railpack пишет «не смог определить способ сборки»

Если в логах сборки видно что-то вроде:

```
Содержимое приложения содержит: ./
└── FunGuarant/
```

значит в **корне репозитория** Railway видит только папку `FunGuarant/`, а не файлы проекта. Нужно указать **корневую папку приложения**:

1. В Railway откройте ваш **сервис** (сервис с деплоем).
2. Перейдите в **Settings** (Настройки).
3. Найдите блок **「Root Directory」** / **「Source」** / **「Корневая директория」**.
4. Укажите: **`FunGuarant`** (имя папки, где лежат `requirements.txt`, `Procfile`, `bot/`, `site/`).
5. Сохраните и сделайте **Redeploy**.

После этого сборка должна находить Python-проект и использовать `Procfile` или `start.sh`.

**Вариант без подпапки:** если хотите, чтобы в корне репозитория сразу были `bot/`, `site/`, `requirements.txt`, `Procfile` — инициализируйте Git и пушите именно из папки FunGuarant (чтобы эта папка и была корнем репо), тогда Root Directory в Railway оставляйте пустым.

## Шаг 1: Создание проекта в Railway

1. Зайдите на [railway.app](https://railway.app) и войдите в аккаунт.
2. Нажмите **«New Project»** (Новый проект).
3. Выберите **「Deploy from GitHub repo」**.
4. Разрешите Railway доступ к GitHub и выберите репозиторий с этим проектом.
5. **Если в корне репо только папка FunGuarant** — в настройках сервиса укажите **Root Directory: `FunGuarant`** (см. блок выше).
6. Railway определит сборку по `requirements.txt` и запуск по `Procfile` или `start.sh`.

---

## Шаг 2: Настройка переменных окружения

В проекте Railway откройте ваш **сервис** (один деплой из репозитория), затем:

1. Перейдите во вкладку **«Variables»**.
2. Добавьте переменные (кнопка **«New Variable»** или **«RAW Editor»**):

| Переменная        | Описание                          | Пример / обязательность |
|-------------------|-----------------------------------|--------------------------|
| `BOT_TOKEN`       | Токен Telegram-бота от BotFather | Обязательно              |
| `ADMIN_CHAT_ID`   | Telegram Chat ID первого админа  | Число, например `8435158276` |
| `ADMIN2_CHAT_ID`  | Chat ID второго админа (если есть)| Число или `0`            |
| `NICKNAME_ADMIN`  | Ник админа без @                 | Например `tr2bel`        |
| `NUMBER_QIWI`     | Номер для пополнения (СБП)       | Например `+79261234567`  |
| `TOKEN_QIWI`      | Токен QIWI API (если нужны платежи)| По желанию              |
| `CHAT_BOT_LINK`   | Ссылка на чат бота               | URL или текст            |
| `INSTRUCTION_LINK`| Ссылка на инструкцию             | URL                      |
| `PROCENT`         | Комиссия сервиса (число)         | Например `5`             |

Минимум для работы:

- `BOT_TOKEN`
- `ADMIN_CHAT_ID`
- `NICKNAME_ADMIN`
- `NUMBER_QIWI`

Остальные можно не задавать — подставятся значения по умолчанию из кода.

---

## Шаг 3: Деплой

1. После добавления переменных Railway автоматически пересоберёт и задеплоит проект.
2. Либо нажмите **«Deploy»** / **«Redeploy»** вручную.
3. Дождитесь окончания сборки (Build) и запуска (Deploy). В логах не должно быть ошибок импорта или падения процесса.

---

## Шаг 4: Получение URL сайта

1. В настройках сервиса откройте вкладку **«Settings»**.
2. В блоке **「Networking」** нажмите **「Generate Domain」**.
3. Railway выдаст URL вида:  
   `https://ваш-проект.up.railway.app`
4. Этот URL — адрес вашего сайта и API. Его нужно использовать в Telegram Mini App и при настройке бота.

---

## Шаг 5: Проверка работы

1. **Сайт**  
   Откройте в браузере:  
   `https://ваш-проект.up.railway.app`  
   Должна открыться главная страница.

2. **Бот**  
   Напишите боту в Telegram команду `/start`.  
   Если в логах Railway нет ошибок и переменная `BOT_TOKEN` задана верно, бот должен ответить.

3. **API**  
   Откройте в браузере:  
   `https://ваш-проект.up.railway.app/api/about`  
   Должен вернуться JSON с информацией о боте.

## Важные замечания

### База данных

- Сейчас используется файл SQLite (`db.db`) в корне проекта.
- На Railway при каждом пересоздании контейнера файловая система может сбрасываться, то есть **данные в `db.db` могут теряться**.
- Для постоянного хранения данных позже можно:
  - подключить к проекту **PostgreSQL** в Railway и перейти на него в коде, или
  - использовать **Railway Volume** и прописать путь к БД в `DATABASE_PATH`.

### Локальный запуск перед деплоем

Из корня проекта:

```bash
# Установка зависимостей
pip install -r requirements.txt

# Запуск (сайт + бот в одном процессе)
# Задайте переменные окружения или создайте .env
set BOT_TOKEN=ваш_токен
set ADMIN_CHAT_ID=ваш_chat_id
python site/backend/app.py
```

Сайт будет доступен по адресу: `http://localhost:5000`.

### Структура для Railway

- **Корень репозитория** — корень проекта (где лежат `requirements.txt` и `Procfile`).
- **Команда запуска** задаётся в `Procfile`:  
  `web: python site/backend/app.py`
- Один процесс поднимает и **Flask (сайт + API)**, и **Telegram-бота** в фоне.

## Частые проблемы

| Проблема | Что проверить |
|----------|----------------|
| Бот не отвечает | В Variables задан `BOT_TOKEN`, после изменений сделан Redeploy. |
| **Ошибка 409 Conflict / getUpdates** | Одновременно работает только один процесс с этим токеном. Остановите бота на своём ПК (закройте скрипт/терминал) и оставьте запущенным только на Railway. После этого бот на Railway через 30 сек сам переподключится. |
| 502 / ошибка при открытии сайта | В логах сервиса смотреть ошибки Python; проверить, что в коде нет жёстко прописанного порта — используется `PORT` из окружения. |
| **API 401 «Не авторизован»** | Так бывает, если открывать сайт в обычном браузере. Mini App должен открываться **из Telegram** (кнопка меню бота или команда). Тогда Telegram передаёт `initData`, и API вернёт 200. В BotFather укажите URL вашего сайта как Web App URL. |
| Импорт `bot` падает | Запуск должен идти из корня проекта (`python site/backend/app.py`), чтобы в `sys.path` была папка с `bot`. |
