# Настройка системы авторизации через Deep Linking

## Обзор

Реализована система авторизации пользователей через Telegram бота с использованием deep linking. При возникновении ошибки 401 Unauthorized пользователю показывается кнопка "Войти", которая перенаправляет к боту для получения уникальной авторизационной ссылки.

## Как это работает

1. **Ошибка 401**: Когда пользователь не авторизован в веб-приложении, появляется модальное окно с кнопкой "Войти"
2. **Генерация ссылки**: При нажатии создается уникальный токен и deep link для бота
3. **Переход к боту**: Пользователь переходит к боту по ссылке вида `https://t.me/username_bot?start=auth_TOKEN`
4. **Авторизация в боте**: Бот проверяет токен и отправляет сообщение с кнопкой для возврата на сайт
5. **Завершение**: Пользователь возвращается на сайт уже авторизованным

## Настройка переменных окружения

Добавьте следующие переменные окружения в Railway (или вашу платформу):

```bash
BOT_TOKEN="ваш_токен_бота"
BOT_USERNAME="имя_пользователя_бота"  # без @
SITE_URL="https://ваше_приложение.railway.app"  # URL вашего сайта
```

## Файлы, которые были изменены

### Backend (`site/backend/app.py`)
- Добавлены эндпоинты:
  - `POST /api/auth_link` - генерация авторизационной ссылки
  - `GET /api/verify_token/<token>` - проверка токена
- Добавлено хранилище временных токенов
- Добавлена периодическая очистка истекших токенов

### Bot (`bot/main.py`)
- Обновлен обработчик команды `/start` для поддержки deep linking
- Добавлена функция `handle_auth_start()` для обработки авторизации
- При получении `auth_TOKEN` бот проверяет токен и отправляет кнопку для входа

### Frontend (`site/frontend/js/app.js`)
- Обновлен обработчик ошибок 401 в `apiRequest()`
- Добавлены функции:
  - `showAuthModal()` - показ модального окна авторизации
  - `generateAuthLink()` - генерация ссылки
  - `checkAuthReturn()` - обработка возврата с бота
- Обновлена функция `showModal()` для поддержки постоянных модальных окон

### Config (`bot/config.py`)
- Добавлена переменная `BOT_USERNAME`

## Процесс авторизации пользователя

1. Пользователь открывает веб-приложение
2. Если не авторизован, появляется ошибка 401
3. Показывается модальное окно с кнопкой "Войти"
4. При нажатии генерируется уникальный токен
5. Пользователь переходит к боту по deep link
6. Бот проверяет токен и отправляет сообщение с кнопкой "Перейти на сайт"
7. Пользователь нажимает кнопку и возвращается на сайт авторизованным

## Безопасность

- Токены действительны 15 минут
- Каждый токен уникален для каждого пользователя
- Автоматическая очистка истекших токенов каждые 5 минут
- Проверка токена перед авторизацией

## Тестирование

Для тестирования системы:

1. Установите все переменные окружения
2. Перезапустите приложение
3. Откройте веб-приложение в режиме инкогнито (чтобы сбросить авторизацию)
4. Попробуйте получить доступ к защищенным функциям
5. Убедитесь, что появляется модальное окно авторизации
6. Проверьте весь процесс авторизации

## Возможные проблемы

1. **BOT_USERNAME не указан**: Убедитесь, что переменная окружения задана правильно
2. **SITE_URL недоступен**: Проверьте, что сайт доступен по указанному URL
3. **Токен не работает**: Убедитесь, что время на сервере синхронизировано
4. **Бот не отвечает**: Проверьте токен бота и что бот запущен
